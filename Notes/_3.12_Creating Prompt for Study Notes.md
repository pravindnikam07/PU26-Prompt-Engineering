# Unit 3: Prompt Engineering Techniques

## Topic 12: Creating Prompt for Study Notes

### Learning Objectives

After studying this topic, students will be able to:

* Create effective prompts for generating **study notes**.
* Specify the required level, syllabus, and topics.
* Use RTCCO to structure a study-notes prompt.
* Control the format and length of generated notes.

---

## 1. Study Notes Prompt

A **Study Notes Prompt** is a prompt used to instruct AI to create learning material for a specific subject or topic.

A good study-notes prompt should clearly specify:

* Subject/topic
* Student level
* Required concepts
* Depth of explanation
* Examples
* Constraints
* Output format

---

## 2. Basic Study Notes Prompt

### Simple Prompt

```text
Create notes on Data Structures.
```

This is too general.

### Improved Prompt

```text
Create study notes on Stack for second-year engineering students.

Include:
- Definition
- LIFO concept
- Operations
- Applications
- Example

Use simple language and headings.
```

## 3. Study Notes Using RTCCO

### Role

```text
Act as an experienced Data Structures instructor.
```

### Task

```text
Create study notes on Stack.
```

### Context

```text
The notes are for second-year engineering students
who have basic knowledge of programming.
```

### Constraints

```text
Use simple language.
Cover only the important concepts.
Include one real-world example and one C++ example.
```

### Output Format

```text
Use:
1. Definition
2. Key Concepts
3. Operations
4. Example
5. C++ Example
6. Quick Revision
```

---

## 4. Complete Study Notes Prompt

```text
Act as an experienced Data Structures instructor.

Create study notes on "Stack" for second-year
engineering students.

Context:
Students have basic knowledge of C++.

Cover:
- Definition of Stack
- LIFO principle
- Stack operations
- Applications of Stack

Constraints:
- Use simple and student-friendly language.
- Include one real-world analogy.
- Include one simple C++ example.
- Avoid unnecessary advanced concepts.

Output Format:
1. Definition
2. Concept
3. Operations
4. Real-world Example
5. C++ Example
6. Applications
7. Quick Revision
```

---

## 5. Study Notes with Syllabus Context

Providing syllabus information can make the generated notes more relevant.

```text
Act as a university instructor.

Create study notes on "Binary Search".

Context:
- Subject: Data Structures
- Level: Second-year engineering
- Students know basic C++.
- The topic is part of the searching techniques unit.

Cover only:
- Definition
- Working principle
- Algorithm
- Example
- Time complexity
- C++ implementation

Constraints:
- Use simple language.
- Explain the algorithm step-by-step.
- Do not include topics outside Binary Search.

Output Format:
Use headings, bullet points, a dry run table, and C++ code.
```

## 6. Controlling the Output

The same topic can produce different notes depending on the required format.

### Bullet Points

```text
Create concise study notes on Operating System.
Use only bullet points.
Cover the key concepts in 300 words.
```

### Table

```text
Create study notes comparing Process and Thread.

Present the comparison in a table with:
Feature | Process | Thread
```

### Structured Notes

```text
Create study notes on Recursion using this structure:

1. Definition
2. Basic Concept
3. Working
4. Example
5. Advantages
6. Limitations
7. Applications
8. Quick Revision
```

## 7. Prompt Optimization for Study Notes

### Before

```text
Explain DBMS.
```

### After

```text
Act as a DBMS instructor.

Create study notes on "Normalization" for third-year
engineering students.

Cover:
- Need for normalization
- 1NF
- 2NF
- 3NF
- Simple example

Constraints:
- Use simple language.
- Explain each normal form with an example.
- Keep the notes within 1000 words.

Output Format:
Use headings, tables, and examples.
```

The optimized prompt produces notes that are more **focused, structured, and suitable for the intended students**.

---

## Best Practices

* Specify the **exact topic**.
* Mention the **student level**.
* Provide syllabus context when necessary.
* List the concepts that must be covered.
* Specify the required depth.
* Use constraints to avoid unnecessary content.
* Specify the output structure.
* Request examples when they improve understanding.
* Keep the prompt focused on the learning objective.
