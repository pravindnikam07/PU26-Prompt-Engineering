UNIT 1 – Introduction to LLM (Generative AI) and Prompt Engineering

Topic 7: Exploring and Comparing Different LLMs

LLMs covered in this topic:

* ChatGPT
* Claude
* Google Gemini
* Grok
* DeepSeek

Important: AI models and their features change frequently. The purpose of this topic is to teach students how to evaluate and compare AI systems, rather than memorize a permanent feature list.

⸻

Learning Objectives

After completing this topic, students will be able to:

* Explain what an LLM is.
* Identify major modern LLM platforms.
* Understand that different LLMs may have different strengths.
* Compare LLMs using a systematic evaluation framework.
* Perform the same task across multiple AI models.
* Evaluate responses for accuracy, relevance, reasoning, and usability.
* Select an appropriate AI tool for a particular task.
* Understand why model comparisons can become outdated.

⸻

1. Introduction

There is no single AI model that is automatically the best for every task.

Different AI systems may perform differently depending on:

* The task
* Prompt quality
* Model version
* Context size
* Available tools
* Language
* Coding requirements
* Multimodal requirements
* Speed
* Cost
* Reliability

For example, one model may be excellent for coding, another may be particularly convenient for working with long documents, while another may provide strong integration with a particular ecosystem.

Therefore, instead of asking:

“Which AI is best?”

a better question is:

“Which AI is best for this particular task and requirement?”

8. Important Concept: Model ≠ Application

Students often confuse an AI model with an AI application.

For example:

AI Model
   ↓
Provides intelligence
   ↓
Application / Interface
   ↓
User interaction

A platform may provide access to multiple models.

Therefore, when comparing AI systems, ask:

1. Which model is being used?
2. What tools are available?
3. What is the context limit?
4. What input/output modalities are supported?
5. What are the usage limits?
6. What is the pricing?
7. How reliable is it for my task?

⸻

9. How Should We Compare LLMs?

Never compare models only by asking:

“Which one gives the longest answer?”

Longer does not necessarily mean better.

Instead, evaluate multiple dimensions.

⸻

LLM Evaluation Framework

Use the following 8 criteria.

Criterion	Question
Accuracy	Is the information correct?
Relevance	Does it answer the actual question?
Reasoning	Does it handle complex tasks effectively?
Instruction Following	Does it follow the prompt?
Coding	Can it generate and explain useful code?
Writing	Is the output clear and well-written?
Multimodal Ability	Can it work with text, images, audio, etc.?
Usability	Is the interface convenient for the task?

Additional practical criteria can include:

* Speed
* Cost
* Context handling
* Tool integration
* Privacy and organizational controls
* Availability

⸻

10. The Same Prompt Test

One of the best ways to compare AI models is to give them exactly the same prompt.

For example:

Explain recursion to a first-year Computer Science student using a real-life analogy, a C++ example, a diagram, and a complexity analysis. Limit the answer to 500 words.

Run this prompt in:

* ChatGPT
* Claude
* Gemini
* Grok
* DeepSeek

Then compare the results.

⸻

11. Fair Comparison

For a meaningful comparison, keep the following constant:

Same Task
    ↓
Same Prompt
    ↓
Same Information
    ↓
Same Evaluation Criteria
    ↓
Compare Outputs

Otherwise, the experiment is unfair.

14. Why AI Responses Differ

Students may ask:

“Why did the same prompt produce different answers?”

Possible reasons include:

1. Different Models

Models have different:

* Architectures
* Training methods
* Data
* Fine-tuning
* Optimization strategies

⸻

2. Different System Instructions

AI platforms may apply additional instructions that users do not see.

⸻

3. Different Tools

One platform may have access to:

* Web search
* Code execution
* File analysis
* Image generation
* External integrations

while another may not.

⸻

4. Model Version

AI companies regularly update models.

Therefore:

A comparison performed today may produce different results several months later.

15. Model Comparison Is Task-Dependent

Consider these tasks:

Task	What to Evaluate
Coding	Correctness, debugging, explanation
Mathematics	Correct reasoning and final answer
Writing	Clarity, tone, structure
Research	Source quality and factual accuracy

A model that performs best in one category may not perform best in another.

18. Advanced Student Experiment

Ask every model the following question:

“What is the output of this C++ program?”

Then provide a program containing a subtle bug.

Students should compare:

* Did the model identify the bug?
* Did it explain why?
* Did it give the correct output?
* Did it hallucinate?
* Did it provide a corrected program?

This introduces students to an important concept:

AI evaluation requires testing, not just reading.

19. Prompt Engineering Connection

This topic directly connects to Prompt Engineering.

Suppose Model A gives a poor response.

Don’t immediately conclude:

“Model A is bad.”

Try improving the prompt.

Prompt 1

Explain recursion.

Prompt 2

You are a Computer Science professor. Explain recursion to a first-year student using a simple real-world analogy, a C++ example, and a step-by-step explanation. Avoid advanced terminology.

Now compare again.

This demonstrates:

Model Performance
        +
Prompt Quality
        +
Tools / Context
        ↓
Final Output

20. Best Practices When Comparing AI Models

1. Use the same prompt

Do not change the question for each model.

2. Test multiple tasks

One task is not enough.

3. Use objective criteria

Do not simply say:

“I like this answer.”

Explain why.

4. Verify factual claims

AI-generated content can contain errors.

5. Test generated code

Never assume generated code is correct.

Compile and execute it.

6. Consider current capabilities

Models and product features change.

7. Don’t judge only by answer length

Concise answers can be better than unnecessarily long ones.

21. Common Mistakes

Mistake	Better Approach
Declaring one model universally best	Choose based on task
Comparing different prompts	Use identical prompts
Looking only at writing quality	Evaluate accuracy and usefulness
Trusting AI-generated facts	Verify important claims
Copying AI code without testing	Compile and test
Comparing outdated model versions	Record model/version and date
Assuming a benchmark proves everything	Test your actual use case

22. Important Concept: Benchmark vs Real-World Testing

AI companies and researchers often use benchmarks to evaluate models.

A benchmark is a standardized test.

For example:

Model A → 85%
Model B → 88%

It might appear that Model B is better.

But this doesn’t necessarily mean Model B is better for your specific task.

For a student:

The best model is the one that performs reliably for the tasks you actually need.

23. Responsible AI Evaluation

When evaluating AI systems:

* Don’t upload confidential data.
* Don’t use private student information.
* Don’t upload passwords or API keys.
* Don’t upload sensitive organizational documents without authorization.
* Follow the terms and policies of the AI service.

Quick Revision

* ChatGPT, Claude, Gemini, Grok, and DeepSeek are examples of modern AI platforms/model families.
* Different AI systems may have different strengths.
* There is no permanent “best LLM” for every task.
* LLMs should be evaluated using criteria such as accuracy, relevance, instruction following, reasoning, coding ability, and usability.
* Fair comparison requires the same prompt and comparable conditions.
* AI models and their capabilities change rapidly.
* Real-world testing is often more useful than relying solely on general benchmarks.
* Prompt quality significantly influences the usefulness of AI output.

⸻

Summary

Modern AI offers users a growing choice of powerful LLM platforms, including ChatGPT, Claude, Gemini, Grok, and DeepSeek. Each platform may have different models, tools, interfaces, strengths, and limitations, and these characteristics can change over time. Therefore, students should avoid memorizing a simple ranking of “best AI models.” Instead, they should learn to evaluate AI systems systematically.

The most important professional skill is not knowing which AI is currently ranked first. It is knowing how to select, prompt, test, verify, and evaluate an AI system for a particular problem.
