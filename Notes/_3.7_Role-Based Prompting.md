# UNIT 3 – Prompt Engineering Techniques

# Topic 7: Role-Based Prompting

## Learning Objectives

After completing this topic, students will be able to:

* Define Role-Based Prompting.
* Understand how assigning a role influences AI responses.
* Create effective role-based prompts.
* Apply Role-Based Prompting to teaching, coding, analysis, and other tasks.
* Understand the difference between a role and a task.

---

## 1. Definition

> **Role-Based Prompting is a technique in which a specific role or professional function is assigned to the AI to guide the perspective, language, expertise, and style of its response.**

### Basic Structure

```text
Role
 ↓
Task
 ↓
AI Response
```

---

## 2. Simple Analogy

The same question can be answered differently depending on who is answering it.

For example:

> "Explain Artificial Intelligence."

A:

* **School teacher** may use simple language and examples.
* **Software engineer** may focus on implementation.
* **Researcher** may discuss technical concepts and limitations.
* **Business analyst** may focus on applications and business impact.

The role influences the **perspective and style** of the response.

---

# 3. Basic Example

### Without Role

```text
Explain binary search.
```

### With Role

```text
Act as a Data Structures instructor.

Explain binary search to undergraduate IT students.
Use simple language and a small example.
```

The second prompt establishes the desired perspective and audience.

---

# 4. Role-Based Prompt Structure

A practical structure is:

```text
Act as a [ROLE].

Task:
[TASK]

Context:
[CONTEXT]

Constraints:
[CONSTRAINTS]

Output Format:
[FORMAT]
```

Example:

```text
Act as a C++ programming instructor.

Task:
Explain pointers.

Context:
The audience is beginner-level programming students.

Constraints:
Use simple language and one example.

Output Format:
Definition → Example → Key Points
```

---

# 5. Role-Based Prompt for Teaching

```text
Act as an experienced university lecturer.

Create study notes on Operating Systems.

Requirements:
- Use clear language.
- Include important definitions.
- Give simple examples.
- Organize the content using headings.
- Keep the content suitable for undergraduate students.
```

---

# 6. Role-Based Prompt for Coding

```text
Act as a senior C++ developer.

Write a C++ program to implement binary search.

Requirements:
- Use standard C++.
- Keep the code readable.
- Include comments.
- Explain the algorithm.
- Provide time and space complexity.
```

The role helps establish the expected technical perspective.

---

# 7. Role-Based Prompt for Code Review

```text
Act as a senior software engineer.

Review the following C++ code.

Check:
1. Correctness
2. Readability
3. Efficiency
4. Potential errors
5. Time complexity
6. Space complexity

Provide specific improvements.
```


# 13. Role vs Task

These two concepts must not be confused.

### Role

Defines:

> **Who or what perspective should the AI adopt?**

Example:

> Act as a software engineer.

### Task

Defines:

> **What should the AI do?**

Example:

> Review the following C++ code.

Together:

```text
Role:
Software Engineer

Task:
Review C++ code
```

---

# 14. Role-Based Prompting and Persona Prompting

Role-Based Prompting and Persona Prompting are closely related, but they emphasize different things.

### Role

Focuses mainly on a **professional function or responsibility**.

Examples:

* Teacher
* Software developer
* Research assistant
* Data analyst
* Career advisor

### Persona

Can define a broader **character, communication style, background, or identity**.

Example:

> Explain this topic like a patient teacher who uses everyday analogies and encourages beginners.

Both can influence the response, but the **role** primarily establishes the task perspective.

---

# 15. Combining Role with RTC CO

Role-Based Prompting can be combined with the prompt structure:

> **Role + Task + Context + Constraints + Output Format**

Example:

```text
ROLE:
Act as a Data Structures instructor.

TASK:
Explain binary search.

CONTEXT:
Audience: Second-year IT students.

CONSTRAINTS:
Use simple language and one example.

OUTPUT FORMAT:
Definition → Working → Example → Complexity
```

This creates a more controlled prompt than using a role alone.

---

# 16. Advantages

* Establishes a clear perspective.
* Helps control tone and terminology.
* Useful for domain-specific tasks.
* Can make responses more suitable for a target audience.
* Useful for teaching, coding, analysis, and writing.

---

# 17. Limitations

* Assigning a role does not make the AI a real professional.
* A role cannot guarantee factual accuracy.
* A vague role may have little effect.
* The task and constraints are still important.
* Important information should still be verified.

For example:

> "Act as a doctor."

does not guarantee that the generated medical information is correct.

---

# 18. Best Practices

### Do

* Choose a role relevant to the task.
* Clearly define the task.
* Specify the target audience.
* Add relevant constraints.
* Define the required output format.

### Avoid

* Using an unrelated role.
* Assuming the role guarantees expertise.
* Using role instructions instead of clear task instructions.
* Assigning exaggerated authority to the AI.

```text
Role
 ↓

 ↓

 ↓

 ↓
```
