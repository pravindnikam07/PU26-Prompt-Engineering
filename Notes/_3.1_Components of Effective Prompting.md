# UNIT 3 – Prompt Engineering Techniques

# Topic 1: Components of Effective Prompting

---

## Learning Objectives

After completing this topic, students will be able to:

- Understand what makes a prompt effective.
- Identify the major components of a high-quality prompt.
- Distinguish between vague and well-defined prompts.
- Apply **Role, Task, Context, Constraints, and Output Format** effectively.
- Understand how specificity and clarity affect AI responses.
- Create structured prompts for academic and professional tasks.
- Evaluate and improve existing prompts.
- Apply prompting best practices to real-world problems.

---

# 1. Introduction

A **prompt** is the instruction or input provided to an AI model to obtain a desired response.

For example:

> Explain machine learning.

This is a valid prompt, but it is very broad.

A more effective prompt is:

> Act as a computer science teacher. Explain machine learning to first-year B.Tech students using simple language and one real-world analogy. Compare supervised and unsupervised learning in a table and keep the explanation below 500 words.

The second prompt gives the AI much more useful information.

### Key Principle

> **Better instructions → Better-controlled output**

However, a longer prompt is **not automatically a better prompt**.

The goal is:

> **Relevant detail + clear instructions + appropriate constraints**

---

# 2. What Makes a Prompt Effective?

An effective prompt should generally provide:

1. **Role** – Who should the AI act as?
2. **Task** – What should it do?
3. **Context** – What information does it need?
4. **Constraints** – What limitations or requirements should it follow?
5. **Output Format** – How should the response be presented?

A useful classroom formula is:

> ## **R + T + C + C + O**

Where:

- **R** = Role
- **T** = Task
- **C** = Context
- **C** = Constraints
- **O** = Output Format

# 3. The RTC C O Framework

```text
                 EFFECTIVE PROMPT
                       │
       ┌───────────────┼───────────────┐
       ↓               ↓               ↓
     ROLE             TASK           CONTEXT
       │               │               │
       └───────────────┼───────────────┘
                       ↓
                 CONSTRAINTS
                       ↓
                 OUTPUT FORMAT
```

This framework provides a practical way for beginners to construct prompts.

# 4. Component 1 – Role

## What is Role?

The **role** tells the AI what perspective, expertise, or function it should adopt for the task.

### Examples

```text
Act as a mathematics teacher.
```

```text
Act as a technical interviewer.
```

```text
Act as a professional resume writer.
```

```text
Act as a C++ programming instructor.
```

```text
Act as a research assistant.
```

---

## Why Use a Role?

Compare:

### Without Role

> Explain binary search.

### With Role

> Act as a DSA instructor teaching first-year engineering students. Explain binary search using a simple analogy and a C++ example.

The second prompt provides additional context about the expected explanation.

---

# 5. Important Note About Role

Students should understand that:

> **Role does not magically give the AI real-world credentials or guarantee expertise.**

For example:

> Act as a medical doctor.

does not mean the response should automatically be treated as professional medical advice.

Similarly:

> Act as a lawyer.

does not guarantee legally authoritative advice.

Role is primarily a **prompting technique for guiding the response's perspective and style**.

# 10. Component 3 – Context

## What is Context?

**Context** provides background information that helps the AI understand the situation.

Consider:

> Create a lesson plan.

The AI doesn't know:

- Subject
- Student level
- Duration
- Learning objectives
- Prior knowledge

A better prompt:

> Create a 60-minute lesson plan on process scheduling for second-year B.Tech IT students. Students already understand basic operating-system concepts.

Now the AI has useful context.

---

# 11. Context Can Include

Context may include:

- Target audience
- Current situation
- Background information
- Existing content
- Previous decisions
- Available resources
- Skill level
- Purpose
- Relevant data

---

# 12. Example – Context

### Weak

> Create interview questions.

### Better

> Create interview questions for final-year Computer Science students applying for entry-level software developer positions. The students know C++, Java, SQL, and basic data structures.

The context helps determine the difficulty and relevance of the questions.

# 13. Component 4 – Constraints

## What Are Constraints?

Constraints define **what the AI should or should not do**.

Examples:

- Maximum length
- Language level
- Number of examples
- Required sections
- Topics to avoid
- Programming language
- Tone
- Complexity level

---

# 14. Examples of Constraints

```text
Keep the explanation below 500 words.
```

```text
Use simple English.
```

```text
Provide exactly 10 MCQs.
```

```text
Use C++ for all code examples.
```

```text
Do not use technical jargon unless explained.
```

```text
Include exactly three examples.
```

---

# 15. Why Constraints Matter

Suppose you ask:

> Explain operating systems.

The response could be:

- 100 words
- 1,000 words
- beginner level
- advanced level
- theoretical
- example-based

The AI has many possible interpretations.

Add constraints:

> Explain operating systems to first-year engineering students in approximately 500 words. Use simple language, three real-world examples, and a comparison table.

Now the desired output is much clearer.

---

# 16. Types of Constraints

### 1. Length Constraint

> Keep the answer below 300 words.

### 2. Quantity Constraint

> Provide five examples.

### 3. Language Constraint

> Use simple English.

### 4. Technical Constraint

> Use C++17.

### 5. Content Constraint

> Focus only on process scheduling.

### 6. Style Constraint

> Use a professional tone.

### 7. Exclusion Constraint

> Do not include advanced mathematical concepts.

# 17. Component 5 – Output Format

## What is Output Format?

Output format tells AI **how the final response should be organized**.

Examples:

- Paragraph
- Bullet points
- Table
- JSON
- Numbered list
- Step-by-step format
- Markdown
- Code
- Question-answer format

# 21. Why Output Format Matters

Suppose a student asks:

> Compare TCP and UDP.

AI might produce several paragraphs.

If the student needs exam notes:

```text
Compare TCP and UDP in a table with:

Feature | TCP | UDP
```

The same information becomes much easier to study.

# 22. Combining All Five Components

Let's construct a complete prompt.

### Role

> Act as a DSA instructor.

### Task

> Explain binary search.

### Context

> The students are second-year B.Tech IT students who understand arrays and loops.

### Constraints

> Use simple English, one analogy, and a C++ example. Keep it below 600 words.

### Output Format

> Use headings, a step-by-step explanation, code, and a complexity table.

---

# 23. Complete Prompt

```text
Act as an experienced DSA instructor.

Task:
Explain binary search.

Context:
The audience is second-year B.Tech IT students who understand
arrays, loops, and basic searching techniques.

Constraints:
- Use simple English.
- Include one real-world analogy.
- Include a C++ implementation.
- Explain the algorithm step by step.
- Keep the explanation below 600 words.

Output Format:
1. Definition
2. Analogy
3. Algorithm
4. C++ Code
5. Dry Run
6. Time and Space Complexity
7. Key Takeaways
```

# 24. Before and After

### ❌ Weak Prompt

> Explain binary search.

### ✅ Improved Prompt

> Act as a DSA instructor. Explain binary search to second-year B.Tech IT students who understand arrays and loops. Use a simple analogy, provide a C++ implementation, perform a dry run using a small sorted array, and explain time and space complexity. Use headings and keep the answer below 600 words.

# 26. The Specificity Principle

A useful principle is:

> **Be specific about what matters.**

Bad:

> Give me information about computers.

Better:

> Explain the five major components of a computer system to first-year engineering students using simple language and one real-world analogy.

---

# 27. But Don't Over-Prompt

More instructions do not always mean better results.

### Overloaded prompt

```text
Explain binary search in 400 words using simple English,
but also advanced terminology, include five analogies,
three C++ programs, Java code, Python code, history,
applications, interview questions, MCQs, research references,
a poem, and a story...
```

This contains too many unrelated requirements.

### Better

Focus on the actual learning objective.

> Explain binary search with one analogy, one C++ implementation, one dry run, and complexity analysis.

---

# 28. Relevance Principle

Every instruction should contribute to the task.

Ask:

> **Does this instruction help achieve my intended output?**

If not, remove it.

This makes prompts:

- Clearer
- Shorter
- Easier to maintain
- Easier to modify

---

# 29. Context vs Constraint

Students commonly confuse these.

### Context

Explains the **situation**.

> The students are beginners who know basic C++.

### Constraint

Defines a **requirement or limitation**.

> Use only basic C++ syntax.

### Easy Way to Remember

> **Context = What the AI should know**

> **Constraint = What the AI should follow**

---

# 30. Task vs Output Format

Another common confusion.

### Task

> Create 10 interview questions.

### Output Format

> Present them in a table with columns: Question, Difficulty, Topic.

So:

> **Task = What to produce**

> **Output Format = How to present it**

---

# 31. Role vs Context

### Role

> Act as a programming instructor.

### Context

> The learners are first-year students who know variables and loops.

Therefore:

> **Role describes the AI's functional perspective.**

> **Context describes the situation and background.**

---

# 32. The Prompt Quality Ladder

A prompt can be improved progressively.

### Level 1 – Vague

> Explain AI.

### Level 2 – Specific Task

> Explain Generative AI.

### Level 3 – Add Audience

> Explain Generative AI to college students.

### Level 4 – Add Context

> Explain Generative AI to first-year engineering students who know basic AI concepts.

### Level 5 – Add Constraints

> Use simple English and practical examples. Keep it below 500 words.

### Level 6 – Add Output Format

> Structure the response using definition, examples, applications, limitations, and summary.

# 33. Prompt Refinement

Prompt Engineering is often iterative.

```text
Prompt
  ↓
Response
  ↓
Identify Problem
  ↓
Modify Prompt
  ↓
New Response
  ↓
Compare
  ↓
Final Prompt
```

Example:

### First prompt

> Explain recursion.

### Problem

The explanation is too advanced.

### Refined prompt

> Explain recursion to beginners using a simple analogy and a small C++ example. Avoid advanced mathematical terminology.

---

# 34. Give Examples When Necessary

Sometimes instructions alone are insufficient.

Suppose you want a particular style of output.

You can show an example:

```text
Convert the following information into flashcards.

Example:

Input:
"CPU executes instructions."

Output:
Q: What does the CPU do?
A: It executes instructions.

Now convert the following text:
[TEXT]
```

This introduces **example-based prompting**, which students will study in greater detail under **one-shot and few-shot prompting**.

---

# 35. Positive Instructions

Instead of:

> Don't make the explanation difficult.

Prefer:

> Explain the concept using beginner-friendly language.

Instead of:

> Don't write long paragraphs.

Prefer:

> Use short paragraphs of 2–4 sentences.

Positive instructions are often easier to interpret.

---

# 36. Explicit Requirements

Weak:

> Make it good.

Better:

> Make the explanation suitable for beginners, use practical examples, avoid unnecessary jargon, and organize it using headings.

"Good" is subjective.

Specific criteria are easier to follow.

---

# 37. Use Delimiters

When providing large input, clearly separate the content from the instruction.

Example:

```text
Summarize the following notes.

--- BEGIN NOTES ---
[Student notes]
--- END NOTES ---

Requirements:
- Keep the summary below 300 words.
- Preserve important technical terms.
- Use bullet points.
```

This helps distinguish **instructions from data**.

# 48. Prompt Evaluation Checklist

Before submitting a prompt, ask:

### Role

- Did I define an appropriate role?

### Task

- Is the task clear?
- Did I use an actionable verb?

### Context

- Does AI have enough background information?

### Constraints

- Did I specify important requirements?

### Output

- Did I define how I want the answer structured?

### Overall

- Is anything ambiguous?
- Is anything unnecessary?
- Could the prompt be misunderstood?

# 49. Common Prompting Mistakes

| Mistake                    | Problem                      | Solution                        |
| -------------------------- | ---------------------------- | ------------------------------- |
| Too vague                  | AI has to guess              | Add specificity                 |
| No context                 | Output may not fit situation | Add relevant background         |
| No audience                | Wrong complexity             | Define audience                 |
| No constraints             | Output may be too long/short | Add requirements                |
| No format                  | Difficult to use             | Specify structure               |
| Contradictory instructions | Confusing output             | Remove conflicts                |
| Too many instructions      | Unnecessary complexity       | Keep only relevant requirements |
| No examples when needed    | Desired pattern unclear      | Provide example                 |
| No review                  | Errors may remain            | Evaluate output                 |

---

# 50. Important Principle: Prompt ≠ Guarantee

A carefully written prompt can improve the quality and consistency of an AI response, but it does **not guarantee correctness**.

AI systems can still:

- Make factual mistakes
- Misinterpret instructions
- Produce outdated information
- Generate incorrect code
- Make unsupported claims

Therefore:

> **Prompt Engineering improves control; it does not eliminate the need for human judgment.**

# 56. Key Takeaways

1. An effective prompt reduces ambiguity.
2. **Role** establishes the desired perspective.
3. **Task** defines what the AI should do.
4. **Context** provides relevant background.
5. **Constraints** define requirements and limitations.
6. **Output Format** controls presentation.
7. More words do not necessarily mean a better prompt.
8. Instructions should be relevant and non-contradictory.
9. Examples can clarify the desired pattern.
10. AI output should still be reviewed and verified.

> ### **The best prompt is not the longest prompt. It is the prompt that communicates the user's intent clearly enough to produce a useful, appropriate, and controllable result.**
