# Topic 4: Few-Shot Prompting

## Learning Objectives

After completing this topic, students will be able to:

- Define Few-Shot Prompting.
- Understand how multiple examples guide an AI model.
- Differentiate between Zero-Shot, One-Shot, and Few-Shot Prompting.
- Create Few-Shot prompts for common tasks.
- Understand when Few-Shot Prompting is useful.
- Apply Few-Shot Prompting to classification, formatting, and content transformation.

---

## 1. Definition

> **Few-Shot Prompting is a technique in which a small number of examples are provided in the prompt to demonstrate the desired task or pattern before giving the actual input.**

The examples are called **demonstrations**.

### Basic Structure

```text
Instruction
     ↓
Example 1
     ↓
Example 2
     ↓
Example 3
     ↓
New Input
     ↓
AI Output
```

The exact number of examples is not fixed. The important point is that **multiple examples** are provided.

---

## 2. Zero-Shot vs One-Shot vs Few-Shot

| Technique | Examples | Purpose                                       |
| --------- | -------: | --------------------------------------------- |
| Zero-Shot |        0 | Perform task from instructions                |
| One-Shot  |        1 | Demonstrate the task once                     |
| Few-Shot  |      Few | Demonstrate a pattern using multiple examples |

### Easy Memory Trick

> **Zero = 0 examples** > **One = 1 example** > **Few = Few examples**

---

## 3. Basic Few-Shot Prompt

```text
Classify customer feedback as Pricing, Support, or Features.

Example 1:
Feedback: "The subscription is too expensive."
Category: Pricing

Example 2:
Feedback: "The support team has not replied."
Category: Support

Example 3:
Feedback: "The application needs dark mode."
Category: Features

Now classify:
Feedback: "The monthly plan costs too much."
```

Expected output:

```text
Category: Pricing
```

The three examples demonstrate the meaning of each category.

## 4. Few-Shot Classification

Few-shot prompting is particularly useful for classification tasks.

```text
Classify each message as:
- Complaint
- Inquiry
- Request

Examples:

Message: "The application keeps crashing."
Category: Complaint

Message: "What are your subscription plans?"
Category: Inquiry

Message: "Please change my registered email address."
Category: Request

Now classify:
"Can you tell me when the next update will be released?"
```

Expected:

```text
Category: Inquiry
```

---

## 5. Few-Shot Sentiment Classification

```text
Classify each statement as Positive, Negative, or Neutral.

Example 1:
"The product is excellent."
→ Positive

Example 2:
"The application crashes frequently."
→ Negative

Example 3:
"The company released a new version."
→ Neutral

Now classify:
"The new interface is very easy to use."
```

Expected:

```text
Positive
```

---

## 6. Few-Shot Text Transformation

Few-shot examples can demonstrate how text should be transformed.

```text
Convert informal messages into professional language.

Example 1:
Input: "Send me the report ASAP."
Output: "Please send me the report at your earliest convenience."

Example 2:
Input: "Tell me the meeting time."
Output: "Could you please let me know the meeting time?"

Now convert:
Input: "Give me the project details."
```

Expected style:

> "Could you please provide me with the project details?"

---

## 7. Few-Shot Output Formatting

Examples can demonstrate a specific output structure.

```text
Convert the information into the specified format.

Example 1:
Input: Java was developed by Sun Microsystems.
Output:
Topic: Java
Fact: Developed by Sun Microsystems

Example 2:
Input: Python was created by Guido van Rossum.
Output:
Topic: Python
Fact: Created by Guido van Rossum

Now process:
C++ was developed by Bjarne Stroustrup.
```

Expected:

```text
Topic: C++
Fact: Developed by Bjarne Stroustrup
```

## 8. Few-Shot Question Generation

```text
Generate conceptual questions from technical topics.

Example 1:
Topic: Binary Search
Question: Why must binary search operate on sorted data?

Example 2:
Topic: Stack
Question: What is the difference between push and pop operations?

Now generate a question for:
Topic: Queue
```

The examples demonstrate the expected **question style and difficulty**.

## 11. Importance of Example Selection

Few-shot prompting depends heavily on the quality of examples.

Good examples should be:

- Correct
- Relevant
- Clear
- Representative
- Consistent with each other

### Poor examples

If examples contain contradictory classifications, the model may produce unreliable results.

---

## 12. Example Diversity

Examples should cover different forms of the task.

For example, for customer feedback:

```text
"The price is too high." → Pricing
"Billing is confusing." → Pricing

"Support has not replied." → Support
"I cannot contact customer service." → Support

"Add dark mode." → Features
"The search feature is missing." → Features
```

This gives the model broader guidance than a single example for each category.

---

## 13. When to Use Few-Shot Prompting

Few-shot prompting is useful when:

- Zero-shot results are inconsistent.
- One example is insufficient.
- The task has a specific pattern.
- Categories have subtle differences.
- A particular output style is required.
- Several examples can clarify the expected behavior.

---

## 14. Advantages

- Provides clearer task guidance.
- Demonstrates patterns effectively.
- Can improve consistency.
- Useful for specialized classification.
- Helps control output style and format.

---

## 15. Limitations

- Increases prompt length.
- Requires carefully prepared examples.
- Poor examples can lead to poor results.
- Too many examples may unnecessarily increase the prompt size.
- Examples may influence the model's interpretation of the task.

---

## 16. Best Practices

### Do

- Use relevant examples.
- Ensure examples are correct.
- Keep examples consistent.
- Cover important variations.
- Clearly separate examples from the actual input.
- Keep the examples concise.

### Avoid

- Unrelated examples.
- Incorrect examples.
- Contradictory examples.
- Excessively long examples.
- Examples that do not represent the actual task.
