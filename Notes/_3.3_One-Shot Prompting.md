# Topic 3: One-Shot Prompting

---

## Learning Objectives

After completing this topic, students will be able to:

* Differentiate between Zero-Shot and One-Shot Prompting.
* Design effective One-Shot prompts.
* Use examples to control output style and format.

# 1. Introduction

In **Zero-Shot Prompting**, we give the AI a task without providing an example.

But sometimes simply describing the task is not enough.

We may want to show the AI exactly what we mean.

For example:

> Convert a sentence into a question.

This instruction can have many interpretations.

Instead, provide one example:

```text
Input:
The student completed the assignment.

Output:
Did the student complete the assignment?

Now convert:
The teacher explained the topic.
```

The first example demonstrates the expected pattern.

This technique is called:

> ## **One-Shot Prompting**

---

# 2. Definition

> **One-Shot Prompting is a prompting technique in which one example of the desired input-output behavior is provided before asking the AI to perform the task on new input.**

### Basic structure

```text
Instruction
     ↓
One Example
     ↓
New Input
     ↓
AI
     ↓
Output
```

---

# 3. Real-Life Analogy

Imagine a teacher wants students to solve a particular type of mathematics problem.

Instead of explaining every rule verbally, the teacher solves **one problem** on the board.

Then says:

> "Now solve this similar problem."

The solved problem acts as a demonstration.

That is the basic idea of One-Shot Prompting.

---

# 4. Zero-Shot vs One-Shot

### Zero-Shot

```text
Classify the following review as Positive or Negative.

Review:
"The product is excellent."
```

There is no example.

### One-Shot

```text
Classify reviews as Positive or Negative.

Example:
Review: "The product is excellent."
Classification: Positive

Now classify:
Review: "The product stopped working after one day."
```

One example is provided.

---

# 5. Why Use One-Shot Prompting?

A single example can communicate things that are difficult to express through instructions alone.

It can demonstrate:

* Desired format
* Writing style
* Classification behavior
* Transformation pattern
* Level of detail
* Expected terminology
* Relationship between input and output

---

# 6. The Most Important Idea

> **Instructions tell the AI what to do; an example demonstrates how you want it done.**

For example:

### Instruction

> Convert informal text into professional English.

### Example

```text
Input:
Hey, send me the report ASAP.

Output:
Please send me the report at your earliest convenience.
```

Now the AI has a concrete pattern.

---

# 7. Basic One-Shot Template

```text
ROLE:
[Optional role]

TASK:
[Describe the task]

EXAMPLE:
Input:
[Example input]

Output:
[Desired output]

NOW PERFORM THE TASK:
Input:
[New input]

OUTPUT:
[Expected format]
```

# 11. One-Shot Text Transformation


# 12. One-Shot Formalization

Convert informal language into professional language.

```text
Rewrite informal messages as professional workplace messages.

Example:

Informal:
"Can you send me the report ASAP?"

Professional:
"Could you please send me the report at your earliest convenience?"

Now rewrite:

Informal:
"Tell me when the meeting starts."
```

Possible output:

> "Could you please let me know when the meeting is scheduled to begin?"

# 26. One-Shot vs Explicit Instructions

Sometimes instructions are sufficient.

### Instruction-based

> Write each definition in exactly two sentences.

But sometimes an example communicates the expectation more naturally:

```text
Example:

Definition:
Encapsulation is the process of combining data and methods
within a class. It also helps restrict direct access to data.

Now write a definition of inheritance in the same style.
```

The example acts as a style reference.

---

# 27. One-Shot Prompt Structure

A strong One-Shot prompt can be structured as:

```text
┌─────────────────────────────┐
│        ROLE / TASK          │
├─────────────────────────────┤
│         EXAMPLE             │
│ Input → Desired Output      │
├─────────────────────────────┤
│        NEW INPUT             │
├─────────────────────────────┤
│       OUTPUT FORMAT          │
└─────────────────────────────┘
```

---

# 28. Example Placement Matters

Keep the demonstration clearly separated.

### Good

```text
Instruction

Example:
Input: ...
Output: ...

Now perform the same task:
Input: ...
```

### Poor

```text
Input: ...
Output: ...
Input: ...
```

Without clear labels, the model may not know which content is an example and which is the actual task.

---

# 29. Use Delimiters

For longer examples, use delimiters.

```text
TASK:
Convert informal text into professional language.

--- EXAMPLE ---
Input:
"Hey, send the file."

Output:
"Could you please send the file?"
--- END EXAMPLE ---

--- NEW INPUT ---
"Tell me the meeting time."
--- END NEW INPUT ---
```

This makes the prompt easier to interpret.

---

# 30. One-Shot Does Not Mean "One Instruction"

This is an important distinction.

**One-shot** refers to:

> **One example**

It does **not** mean:

> One sentence or one instruction.

A one-shot prompt can still contain:

* Role
* Task
* Context
* Constraints
* Output format
* One example

# 34. One-Shot for Classification with an Edge Case

Suppose we want to classify:

> "The product is expensive, and customer support is slow."

Example:

```text
Feedback:
"The subscription is expensive."

Category:
Pricing
```

Then:

```text
New Feedback:
"The subscription is expensive, and customer support is slow."
```

The AI may still have difficulty deciding the primary category.

### Lesson

> **One example does not guarantee correct behavior.**

If the task contains many edge cases, additional examples or explicit decision rules may be needed.

---

# 35. Choosing a Good Example

A good example should be:

### 1. Representative

It should demonstrate the actual task.

### 2. Clear

The input and output should have an obvious relationship.

### 3. Correct

An incorrect example can teach the wrong pattern.

### 4. Relevant

The example should resemble the actual task.

### 5. Appropriate in complexity

A very simple example may not demonstrate how to handle the actual complexity.

---

Suppose the task is:

> Classify customer complaints into Pricing, Support, or Features.


This example doesn't demonstrate any of the required categories.

Therefore, it is not useful for the task.

# 39. One-Shot Prompt Optimization

Start:

> Classify this feedback.

Add one example:

```text
Example:
"The price is too high." → Pricing

Now classify:
"The support team hasn't replied."
```

Then improve the instructions:

```text
Classify customer feedback into:
- Pricing
- Support
- Features

Example:
Feedback: "The price is too high."
Category: Pricing

Now classify:
"The support team hasn't replied."

Return:
Category + one-sentence reason.
```

The combination is stronger because the model receives both:

* Explicit instructions
* A demonstration

---

# 40. Advantages of One-Shot Prompting

### 1. Demonstrates the desired pattern

The model sees exactly what is expected.

### 2. Controls output format

Useful when the format is unusual.

### 3. Can improve consistency

A relevant example can reduce ambiguity.

### 4. Useful for style imitation

For example:

* Writing style
* Explanation style
* Formatting style

### 5. Low prompt overhead

Only one example is required.

---

# 41. Limitations of One-Shot Prompting

### 1. One example may not cover all cases

A single example cannot demonstrate every possible variation.

### 2. Example can bias the output

If the example is unusual, the model may overgeneralize from it.

### 3. Poor example = poor guidance

An incorrect example can produce incorrect behavior.

### 4. Complex tasks may need multiple examples

Few-shot prompting may be more suitable.

### 5. Example selection matters

The example should represent the intended task accurately.

---

# 42. When Should You Use One-Shot Prompting?

Use it when:

* Zero-shot results are inconsistent.
* The desired format is unusual.
* A single example can clearly demonstrate the pattern.
* You need a specific writing style.
* You want to show one representative classification.
* The task has a simple transformation rule.

---

# 43. When Is One-Shot Not Enough?

Consider Few-Shot Prompting when:

* There are multiple categories.
* There are many edge cases.
* The task has complex rules.
* Several output patterns are possible.
* The model needs to learn distinctions between similar cases.

For example:

```text
Pricing example
Support example
Features example
```

may be better than only:

```text
Pricing example
```

This leads to the next technique:

> **Few-Shot Prompting**

# 52. Best Practices

### Do

* Use one representative example.
* Clearly label example and new input.
* Ensure the example is correct.
* Keep the example relevant.
* Match the example to the desired output.
* Use delimiters for long examples.
* Combine examples with clear instructions.
* Test the prompt with different inputs.

### Don't

* Use an unrelated example.
* Use an incorrect example.
* Give an ambiguous example.
* Assume one example covers every edge case.
* Add an example simply for the sake of adding one.

---

# 53. Common Mistakes

| Mistake                         | Problem                           | Solution                          |
| ------------------------------- | --------------------------------- | --------------------------------- |
| No example                      | Becomes zero-shot                 | Add one demonstration             |
| Wrong example                   | Teaches wrong pattern             | Verify example                    |
| Irrelevant example              | Doesn't guide task                | Use representative example        |
| Unclear labels                  | Input/output relationship unclear | Label clearly                     |
| Example too complex             | Pattern becomes difficult         | Use simple representative example |
| Example contradicts instruction | Confuses model                    | Make them consistent              |
| One example for many edge cases | Insufficient coverage             | Add more examples                 |

# 58. Zero-Shot vs One-Shot – Final Comparison

| Feature            | Zero-Shot             | One-Shot                      |
| ------------------ | --------------------- | ----------------------------- |
| Examples           | 0                     | 1                             |
| Instructions       | Required              | Required                      |
| Demonstration      | No                    | Yes                           |
| Prompt complexity  | Usually lower         | Slightly higher               |
| Format control     | Instruction-based     | Instruction + example         |
| Useful for         | Straightforward tasks | Pattern/style-specific tasks  |
| Edge-case coverage | Limited               | Still limited                 |
| Main advantage     | Simple                | Demonstrates desired behavior |

# 59. Final Takeaway

One-Shot Prompting is useful when simply describing the task is not enough.

Instead of saying:

> **"Do this."**

we say:

> **"Do this. Here is one example of what I mean. Now do it for this new input."**

The key is not merely providing an example, but providing a **clear, correct, relevant, and representative example**.

> ### **Zero-Shot tells AI what to do. One-Shot tells AI what to do and demonstrates one way the result should look.**
