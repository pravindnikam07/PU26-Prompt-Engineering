# UNIT 2 – Fundamental of Prompt Writing

# Topic 4: Writing Good Prompts

---

## Learning Objectives

After completing this topic, students will be able to:

* Explain what makes a prompt effective.
* Identify the characteristics of a good prompt.
* Distinguish between vague, good, and well-engineered prompts.
* Apply clarity, specificity, context, constraints, and output control.
* Avoid common prompting mistakes.
* Improve weak prompts systematically.
* Evaluate prompts based on the quality of their outputs.
* Develop a practical prompt-refinement habit.

---

# 1. Introduction

Writing a prompt is easy.

Writing a **good prompt** is a skill.

Compare:

> Tell me about Python.

with:

> Explain the core concepts of Python to a first-year Computer Science student who knows basic programming. Use simple language, include three short code examples, and organize the explanation under clear headings.

Both are valid prompts.

But the second prompt gives the AI much more useful information about the **desired outcome**.

This leads to an important principle:

> **Good Prompt Engineering is not about writing more. It is about communicating better.**

---

# 2. What Is a Good Prompt?

A good prompt is a prompt that provides **clear, relevant, and sufficient instructions** to help an AI model produce the desired output.

A good prompt should generally answer questions such as:

```text
What do I want?
Who is the audience?
What information does AI need?
What rules should it follow?
What should the final answer look like?
```

Not every prompt needs every element.

---

# 3. The Six Principles of Good Prompt Writing

A practical framework for students is:

```text
        GOOD PROMPT
             │
 ┌───────────┼────────────┐
 │           │            │
Clarity   Specificity   Context
 │           │            │
 └───────────┼────────────┘
             │
      Constraints
             │
      Output Format
             │
        Verification
```

Remember:

> **Clear + Specific + Relevant + Controlled + Verifiable**

---

# 4. Principle 1 – Clarity

## What is Clarity?

The AI should be able to understand what you want without guessing your intention.

### Poor

> Explain networking.

What part of networking?

### Better

> Explain the OSI model.

### Even Better

> Explain the seven layers of the OSI model to a beginner using a simple real-world analogy.

---

# 5. Avoid Vague Language

Words such as:

* Good
* Nice
* Proper
* Professional
* Short
* Detailed
* Interesting
* Better
* Quickly

can be ambiguous.

Instead of:

> Write a short explanation.

Use:

> Explain the concept in approximately 200 words.

Instead of:

> Make my resume better.

Use:

> Review my resume for an entry-level software developer position and identify specific improvements to wording, structure, and technical skills.

---

# 6. Principle 2 – Specificity

## What is Specificity?

Specificity means clearly defining the exact task and desired result.

Compare:

### Vague

> Create questions about Java.

### Specific

> Create 15 multiple-choice questions on Java inheritance for second-year engineering students. Include four options for each question, one correct answer, and a one-sentence explanation.

The second prompt reduces ambiguity.

---

# 7. Specificity Does Not Mean Excessive Detail

A common beginner mistake is:

> "If detailed prompts are good, I should make every prompt extremely long."

This is incorrect.

Consider:

> Translate "Good Morning" into Hindi.

There is no need for a 500-word prompt.

Therefore:

> **Use the minimum useful detail required to achieve the desired result.**

---

# 8. Principle 3 – Relevant Context

AI may need background information to understand the task properly.

Example:

> Explain recursion.

versus:

> Explain recursion to a first-year engineering student who understands loops and functions but has never studied recursive functions.

The second provides relevant context.

---

# 9. Types of Useful Context

Context can include:

### Audience

> First-year engineering students.

### Purpose

> For an examination.

### Background knowledge

> Students understand loops but not recursion.

### Situation

> The email is being sent to a college professor.

### Existing material

> Use the following lecture notes.

### Domain

> This is for an e-commerce application.

---

# 10. Principle 4 – Clear Constraints

Constraints control the boundaries of the task.

Examples:

> Use simple English.

> Keep the response under 500 words.

> Provide exactly 10 questions.

> Use C++17.

> Do not use STL.

> Include only vegetarian options.

---

# 11. Avoid Conflicting Instructions

Consider:

> Explain the topic in 50 words and provide a detailed 2,000-word explanation.

These instructions conflict.

The AI must decide which requirement to prioritize.

Instead:

> Explain the topic in approximately 500 words and focus only on the three most important concepts.

---

# 12. Principle 5 – Control the Output

Tell the AI what the final response should look like when structure matters.

For example:

> Present the comparison in a table.

or:

> Provide the answer as numbered steps.

or:

> Return valid JSON.

or:

> Structure the response as an email.

---

# 13. Example of Output Control

### Without output control

> Compare Java and C++.

The response may be paragraphs, bullets, or a table.

### With output control

> Compare Java and C++ in a table using these columns: Feature, Java, C++.

Now the structure is predictable.

---

# 14. Principle 6 – Verification

A good prompt should consider how the result will be checked.

This is particularly important for:

* Mathematics
* Programming
* Data analysis
* Research
* Factual information
* Structured outputs

Example:

> Solve the equation and verify the result by substituting the answer back into the original equation.

For code:

> Include test cases covering normal input and edge cases.

---

# 15. The Good Prompt Formula

Students can use:

```text
CLEAR TASK
     +
RELEVANT CONTEXT
     +
SPECIFIC REQUIREMENTS
     +
CONSTRAINTS
     +
OUTPUT FORMAT
     +
VERIFICATION (when needed)
```

This is not a rigid formula.

It is a **prompt-design checklist**.

---

# 16. Bad → Good → Excellent

This is one of the most useful exercises for students.

## Example 1 – Study Notes

### Bad

> Make notes on DBMS.

### Good

> Create study notes on database normalization for engineering students.

### Excellent

> Act as a DBMS professor. Create exam-oriented study notes on database normalization for second-year engineering students who understand basic relational databases but are new to normalization. Explain 1NF, 2NF, 3NF, and BCNF using simple examples. Include common mistakes and a short practice section. Use headings, tables, and worked examples.

---

# 17. Example 2 – Email

### Bad

> Write an email to teacher.

### Good

> Write a professional email to my professor requesting an assignment extension.

### Excellent

> Act as a professional communication assistant. Write a polite email to my professor requesting a two-day extension for an assignment. I have completed most of the work but need additional time for testing. Keep the email below 150 words. Do not exaggerate the situation. Include a clear subject line and professional closing.

---

# 18. Example 3 – Coding

### Bad

> Write sorting code.

### Good

> Write a C++ program for Merge Sort.

### Excellent

> Act as a Data Structures instructor. Write a beginner-friendly C++17 implementation of Merge Sort for undergraduate students. Do not use STL sorting functions. Explain the divide-and-conquer approach, include comments in the code, provide sample input/output, and analyze time and auxiliary space complexity.

---

# 19. Example 4 – Resume

### Bad

> Improve my resume.

### Good

> Review my resume for a software developer position.

### Excellent

> Act as a technical recruiter hiring entry-level software developers. Review the attached resume for a software engineering internship. Identify weaknesses in structure, wording, technical skills, and project descriptions. Do not invent qualifications or experience. For each major issue, provide a specific improvement. Present the recommendations in a table.

---

# 20. The "Five Questions" Method

Before sending a prompt, students can ask:

### 1. What?

What exactly do I want AI to do?

### 2. Why?

Why do I need the output?

### 3. Who?

Who will use or read the output?

### 4. What rules?

What constraints must AI follow?

### 5. How?

How should the final answer be presented?

---

# 21. The Specificity Ladder

Students can visualize prompt improvement as a ladder.

```text
Level 1
"AI"

       ↓

Level 2
"Explain AI."

       ↓

Level 3
"Explain Generative AI."

       ↓

Level 4
"Explain Generative AI to beginners."

       ↓

Level 5
"Explain Generative AI to first-year engineering students
using three real-world examples."

       ↓

Level 6
"Explain Generative AI to first-year engineering students
using three real-world examples, simple language, a comparison
with traditional AI, and a short summary table."
```

The goal is not necessarily to reach Level 6 every time.

The goal is:

> **Enough specificity to remove important ambiguity.**

---

# 22. Context Window Awareness

AI models can process large amounts of information, but students should not interpret this as:

> "I can provide unlimited irrelevant information."

Large amounts of unnecessary text can make prompts harder to manage and may distract from the important requirements.

Therefore:

> **Keep the input focused and relevant.**

---

# 23. Give Information in a Structured Way

Instead of:

> I am a student and I want to learn Java and I have an exam next week and I don't understand OOP and please explain everything but don't make it too difficult...

Use:

```text
Background:
I am a second-year engineering student.

Topic:
Java OOP.

Current Knowledge:
I understand basic Java syntax but struggle with OOP.

Goal:
Prepare for my upcoming examination.

Requirements:
- Explain the core OOP concepts.
- Use simple examples.
- Include important exam points.

Output:
Use headings and a comparison table.
```

Structured information is easier to understand and modify.

---

# 24. Use Delimiters for Large Inputs

When providing text, code, or data, separate it clearly from the instructions.

Example:

```text
Task:
Summarize the following article.

Text:
"""
Artificial Intelligence is...
...
...
"""
```

For code:

````text
Review the following code:

```cpp
#include <iostream>
...
````

Focus on correctness and performance.

````

Delimiters help distinguish:

> **Instructions**

from:

> **Information being processed**

---

# 25. Separate Instructions from Data

Consider a summarization task.

### Better structure

```text
TASK:
Summarize the text.

CONSTRAINTS:
- 200 words maximum.
- Preserve important facts.

TEXT:
"""
[article]
"""
````

This is generally clearer than mixing instructions and content together.

---

# 26. Give Examples When the Desired Pattern Is Difficult to Explain

Sometimes describing the desired output is difficult.

In such cases, examples can help.

Example:

```text
Convert the following student feedback into this format:

Example:
Input:
"The lectures are good but the pace is too fast."

Output:
Category: Teaching
Issue: Fast pace
Sentiment: Mixed

Now process:
[NEW FEEDBACK]
```

This introduces the idea of **few-shot prompting**, which we will study in Unit 3.

---

# 27. Avoid Ambiguous Requirements

### Ambiguous

> Give me some questions.

How many?

What difficulty?

What format?

### Better

> Create 10 questions.

### Better still

> Create 10 questions on Operating Systems for second-year engineering students: 5 easy, 3 medium, and 2 difficult.

---

# 28. Define "Good" When It Matters

Suppose you say:

> Write a good introduction.

"Good" can mean many things.

Instead:

> Write a 150-word introduction that clearly defines the topic, explains its importance, and ends with the purpose of the article.

Now "good" has been converted into measurable criteria.

---

# 29. Use Positive Instructions

Instead of only saying what **not** to do, explain what you want.

### Less useful

> Don't make it complicated.

### Better

> Use beginner-friendly language and explain technical terms with simple examples.

---

# 30. Negative Constraints

Negative instructions can still be useful when there is a clear reason.

Examples:

> Do not invent sources.

> Do not use STL.

> Do not include personal information.

> Do not change the original meaning.

But avoid unnecessary lists of restrictions.

---

# 31. One Prompt ≠ One Sentence

A prompt can contain multiple sections.

For complex tasks, a structured prompt is often easier to understand:

```text
ROLE
TASK
CONTEXT
REQUIREMENTS
CONSTRAINTS
OUTPUT
```

This is especially useful for:

* Research
* Coding
* Education
* Data analysis
* Business tasks

---

# 32. Prompt Refinement

One of the most important Prompt Engineering skills is **iteration**.

Don't think:

> I wrote one prompt, therefore I'm done.

Instead:

```text
Prompt
  ↓
AI Output
  ↓
Evaluate
  ↓
Find Problem
  ↓
Modify Prompt
  ↓
Generate Again
  ↓
Compare
```

---

# 33. Example of Prompt Refinement

### Initial Prompt

> Explain machine learning.

### Output Problem

The explanation is too technical.

### Refined Prompt

> Explain machine learning to a first-year engineering student who has no prior knowledge of AI. Use simple language and three everyday examples.

---

### Second Problem

The response is still too long.

### Refined Prompt

> Explain machine learning to a first-year engineering student who has no prior knowledge of AI. Use simple language, three everyday examples, and keep the explanation below 500 words.

This is Prompt Engineering in practice.

# 34. The Prompt Optimization Loop

A useful classroom model:

```text
        ┌───────────────┐
        │    PROMPT     │
        └───────┬───────┘
                ↓
        ┌───────────────┐
        │    OUTPUT     │
        └───────┬───────┘
                ↓
        ┌───────────────┐
        │   EVALUATE    │
        └───────┬───────┘
                ↓
        ┌───────────────┐
        │    REFINE     │
        └───────┬───────┘
                │
                └──────────→ New Prompt
```

# 35. Prompt Evaluation

Students should not evaluate a prompt only by looking at the prompt.

Evaluate the **output**.

A useful evaluation framework:

| Criterion    | Question                               |
| ------------ | -------------------------------------- |
| Relevance    | Did AI answer the actual task?         |
| Accuracy     | Is the information correct?            |
| Completeness | Are important requirements covered?    |
| Clarity      | Is the response understandable?        |
| Format       | Did AI follow the requested structure? |
| Consistency  | Does it follow all constraints?        |
| Usefulness   | Can I actually use the result?         |

---

# 36. Prompt Quality vs Output Quality

An important distinction:

> A well-written prompt does not guarantee a correct answer.

AI can still produce:

* Incorrect facts
* Outdated information
* Hallucinated information
* Incorrect calculations
* Faulty code
* Unsupported claims

Therefore:

> **Prompt quality and output verification are separate responsibilities.**

---

# 37. Verification for Different Tasks

### Mathematics

> Show the calculation and verify the result.

### Programming

> Include test cases and explain edge cases.

### Research

> Distinguish established facts from uncertain claims and provide sources where appropriate.

### Summarization

> Do not introduce information that is absent from the source.

### Data analysis

> State assumptions and explain the calculation.

---

# 38. Common Prompting Mistakes

## Mistake 1 – Too Vague

> Tell me about technology.

### Fix

Specify the topic and objective.

---

## Mistake 2 – No Audience

> Explain recursion.

### Fix

> Explain recursion to a beginner who understands loops.

---

## Mistake 3 – Too Many Unnecessary Instructions

A huge prompt can contain dozens of irrelevant requirements.

### Fix

Keep only instructions that affect the desired output.

---

## Mistake 4 – Conflicting Requirements

> Make it extremely detailed but only 50 words.

### Fix

Prioritize requirements and resolve conflicts.

---

## Mistake 5 – No Output Format

If structure matters, specify it.

---

## Mistake 6 – Asking for "Perfect" Output

> Give me the perfect answer.

"Perfect" is undefined.

Instead define measurable criteria.

---

## Mistake 7 – Blind Trust

Students may assume:

> "AI generated it, so it must be correct."

This is dangerous.

Always verify important information.

---

# 39. Prompt Writing Checklist

Before submitting:

```text
□ Is my task clear?
□ Did I use a specific action?
□ Did I provide relevant context?
□ Did I specify the audience?
□ Did I define important constraints?
□ Did I specify the output format?
□ Did I remove irrelevant information?
□ Are my instructions consistent?
□ Can I verify the result?
```

---

# 40. Before vs After

## Before

> Make a presentation about cybersecurity.

## After

```text
Act as an experienced cybersecurity instructor.

Create an outline for a 10-slide presentation on
cybersecurity awareness for first-year engineering students.

Requirements:
- Use simple language.
- Cover phishing, passwords, malware, social engineering,
  and safe browsing.
- Include one real-world example for each major topic.
- Avoid highly technical security concepts.

Output Format:
For each slide provide:
Slide Number | Title | Key Points | Visual Suggestion
```

The second prompt is easier for the AI to interpret and easier for the user to evaluate.

# 41. Classroom Activity – Bad to Better

Give students:

> "Create a website."

Students must improve it through **three iterations**.

### Version 1

Basic prompt.

### Version 2

Add:

* Purpose
* Target audience
* Technology

### Version 3

Add:

* Features
* Constraints
* Design requirements
* Output format
* Testing requirements

Students compare the outputs.

# 42. Classroom Activity – Find the Problem

Give students this prompt:

```text
Act as an expert.

Make a very detailed but very short article about AI.
Use simple language but include advanced technical details.
Make it creative but completely factual.
Explain everything but keep it under 100 words.
```

Ask:

> What is wrong?

Expected observations:

* "Very detailed" vs "very short"
* Simple language vs advanced technical detail
* "Explain everything" vs 100 words
* "Creative" vs "completely factual" may need clarification depending on the task

Students rewrite it.

---

# 43. Classroom Activity – Prompt Doctor

Give students a deliberately weak prompt:

> Make my LinkedIn post better.

Students diagnose it.

### Questions

* Better for whom?
* What is the purpose?
* What tone?
* What length?
* What information must remain?
* What output is required?

Then create the improved prompt.

# 45. Student Task – A/B Prompt Testing

Create two prompts for the same task.

### Prompt A

Simple version.

### Prompt B

Structured version.

Generate outputs from both.

Compare:

| Criterion    | Prompt A | Prompt B |
| ------------ | -------: | -------: |
| Relevance    |       /5 |       /5 |
| Accuracy     |       /5 |       /5 |
| Completeness |       /5 |       /5 |
| Format       |       /5 |       /5 |
| Usefulness   |       /5 |       /5 |

### Final Question

> Did the more detailed prompt actually produce a better result?

This teaches students to **test rather than assume**.

# 46. Practical Exercise – Improve This Prompt

### Original

> Write an essay on Artificial Intelligence.

### Improved Version

```text
Act as an academic writing instructor.

Write a 1,000-word essay on "The Impact of Generative AI
on Higher Education" for undergraduate students.

Requirements:
- Use a balanced and academic tone.
- Explain both benefits and limitations.
- Include relevant examples.
- Avoid unsupported statistics.
- Clearly distinguish established facts from opinions.

Output Format:
1. Title
2. Introduction
3. Main Discussion
4. Benefits
5. Challenges
6. Conclusion
```

# 47. Best Practices Summary

### Do

* Be clear.
* Be specific.
* Provide relevant context.
* Define important constraints.
* Specify the output format.
* Use structured prompts for complex tasks.
* Separate instructions from input data.
* Use examples when useful.
* Iterate and refine.
* Verify important outputs.

### Don't

* Use unnecessary complexity.
* Add irrelevant information.
* Use vague words without defining them.
* Give conflicting instructions.
* Assume AI is always correct.
* Assume longer prompts are automatically better.
* Use personas unnecessarily.
* Stop after the first output when refinement is needed.

# 48. A Practical Prompt Formula for Students

Students can remember:

> **T + C + R + O + V**

Where:

* **T** = Task
* **C** = Context
* **R** = Requirements/Constraints
* **O** = Output
* **V** = Verification

Combined with the previous RTCCO framework, this gives students a complete mental model for designing prompts.

## A Good Prompt Should Be:

```text

   ↓
SPECIFIC
   ↓
RELEVANT
   ↓
CONSTRAINED
   ↓
STRUCTURED
   ↓

```

### Golden Rule

> **Don't optimize the prompt for length. Optimize it for the quality of the desired outcome.**

---

# Summary

Writing good prompts is one of the fundamental skills of Prompt Engineering. An effective prompt clearly communicates the **task**, provides the **relevant context**, specifies important **requirements and constraints**, and controls the **desired output format** when necessary.

Students should also understand that prompt writing is an **iterative process**. The first prompt does not always produce the best result. A professional approach is to generate an output, evaluate it against defined criteria, identify weaknesses, refine the prompt, and compare the new result.

Most importantly:

> **The objective of a good prompt is not to make AI respond more. It is to make AI respond more usefully.**
