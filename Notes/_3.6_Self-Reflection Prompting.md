# UNIT 3 – Prompt Engineering Techniques

# Topic 6: Self-Reflection Prompting

## Learning Objectives

After completing this topic, students will be able to:

* Define Self-Reflection Prompting.
* Understand how AI can review its own generated output.
* Create prompts that ask AI to evaluate and improve an answer.
* Apply Self-Reflection to writing, coding, mathematics, and summarization.
* Understand its limitations.

---

## 1. Definition

> **Self-Reflection Prompting is a technique in which the AI is instructed to review, evaluate, and improve its own generated response according to specified criteria.**

Instead of accepting the first response, the AI performs an additional review.

### Basic Process

```text
Task
  ↓
Initial Response
  ↓
Review / Evaluate
  ↓
Identify Problems
  ↓
Improve
  ↓
Final Response
```

---

## 2. Simple Analogy

A student writes an answer in an examination.

Before submitting, the student:

1. Reads the answer again.
2. Checks for mistakes.
3. Corrects errors.
4. Submits the improved answer.

Self-Reflection Prompting follows a similar pattern.

---

## 3. Basic Example

### Normal Prompt

```text
Write an explanation of inheritance in Java.
```

### Self-Reflection Prompt

```text
Explain inheritance in Java.

After generating the explanation:

1. Check whether the definition is correct.
2. Check whether the example is correct.
3. Identify any unclear statements.
4. Correct any identified problems.
5. Provide the final improved explanation.
```

The second prompt explicitly asks the AI to **review its response before presenting the final version**.

# 4. Self-Reflection for Study Notes

```text
Create study notes on Binary Search.

After creating the notes, review them for:

1. Technical correctness.
2. Missing important concepts.
3. Incorrect complexity information.
4. Clarity for undergraduate students.

Correct any identified issues and provide the final notes.
```

# 5. Self-Reflection for Code

```text
Write a C++ program to find the largest element in an array.

After generating the code:

1. Check for syntax errors.
2. Check for logical errors.
3. Check boundary conditions.
4. Verify the expected output.
5. Check time and space complexity.
6. Correct any problems.

Provide the final corrected code.
```

---

# 6. Self-Reflection for Mathematics

```text
Solve the following problem:

Find the time complexity of:
for(int i = 1; i < n; i *= 2)
    cout << i;

After solving:

1. Check the number of iterations.
2. Verify the mathematical reasoning.
3. Check the final Big-O notation.
4. Correct any errors.

Then provide the final answer.
```

---

# 7. Self-Reflection for Summarization

```text
Summarize the following article in 150 words.

After creating the summary:

1. Check whether the main idea is included.
2. Check whether important points are preserved.
3. Remove unnecessary information.
4. Ensure that no unsupported information has been added.
5. Provide the final revised summary.
```

# 9. Self-Reflection Criteria

Self-reflection becomes more useful when clear evaluation criteria are provided.

Examples:

```text
Accuracy
Clarity
Completeness
Relevance
Grammar
Formatting
```

Instead of:

> "Check your answer."

use:

> "Check the answer for factual accuracy, completeness, clarity, and formatting."

# 10. Self-Reflection Prompt Structure

```text
TASK
 ↓
GENERATE INITIAL RESPONSE
 ↓
EVALUATION CRITERIA
 ↓
IDENTIFY PROBLEMS
 ↓
REVISE
 ↓
FINAL OUTPUT
```

A practical template:

```text
Task:
[Task]

Requirements:
[Requirements]

After generating the response, review it for:
[Evaluation criteria]

Correct any identified issues.

Return only the final improved response.
```

---

# 11. Self-Reflection vs Step-by-Step Prompting

These techniques are different.

| Technique       | Main Purpose                              |
| --------------- | ----------------------------------------- |
| Step-by-Step    | Divide a task into sequential steps       |
| Self-Reflection | Review and improve the generated response |

They can also be combined.

### Example

```text
1. Solve the problem step by step.
2. Review the solution.
3. Check for errors.
4. Correct any errors.
5. Provide the final answer.
```

This combines **Step-by-Step + Self-Reflection**.

---

# 12. Self-Reflection vs Few-Shot

| Technique       | Main Idea                                   |
| --------------- | ------------------------------------------- |
| Few-Shot        | Provides examples to demonstrate a pattern  |
| Self-Reflection | Reviews and improves the generated response |

A prompt can use both techniques when appropriate.

---

# 13. Advantages

* Encourages review before finalizing.
* Can improve clarity and completeness.
* Useful for identifying obvious errors.
* Useful for writing and code improvement.
* Provides a structured quality-check process.

---

# 14. Limitations

Self-reflection does **not guarantee correctness**.

The AI may fail to identify an error in its own response.

Therefore:

> **Self-reflection is a quality-improvement technique, not a guarantee of factual correctness.**

For important results, independent verification is still necessary.

---

# 15. Best Practices

### Do

* Define specific evaluation criteria.
* Ask the AI to check relevant aspects.
* Ask for corrections after evaluation.
* Use self-reflection for complex outputs.
* Independently verify important facts and calculations.

### Avoid

* Assuming self-reflection makes an answer automatically correct.
* Using vague instructions such as "make it better."
* Adding unnecessary review stages to simple tasks.
* Treating AI's self-evaluation as independent verification.

# 20. Quick Revision

> **Self-Reflection Prompting = Generate → Review → Improve**

```text
Initial Response
       ↓
     Review
       ↓
Find Problems
       ↓
   Correct
       ↓
Final Response
```

### Key Principle

> **Ask the AI not only to generate an answer, but also to evaluate that answer against clearly defined criteria and improve it where necessary.**
